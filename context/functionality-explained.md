# How this app works for a React developer

This project is a Next.js app, but the mental model is still very close to React.

## 1. What Next.js adds on top of React

In a standard React app, you usually have a root component that renders your UI. In a Next.js App Router app, the “page” is a component exported from a route file such as app/page.tsx.

That means:

- app/page.tsx = the root page for /
- app/layout.tsx = the shared shell around all pages
- app/globals.css = global styles and site-wide theme variables
- public/ = static assets such as images, icons, and downloadable files

For a React developer, think of app/page.tsx as the main screen component for the homepage, and app/layout.tsx as the outer app wrapper.

## 2. The app structure is route-based

Next.js uses a file-system router. The folder structure matters:

- app/page.tsx -> homepage route
- app/about/page.tsx -> /about route
- app/contact/page.tsx -> /contact route

This differs from a typical React SPA where routes are usually handled by a router package such as React Router. Here, the routes are created by the folder/file names themselves.

## 3. Server components vs client components

In Next.js 16, the default is a server component. That means a file like app/page.tsx can render JSX without needing a client-side hook system.

You only need to add `"use client"` at the top of a file when you want:

- useState
- useEffect
- event handlers that rely on browser behavior
- client-side interactivity

For this landing page, most of the work will be static markup and styling, so a server component is usually sufficient.

## 4. How styling works here

This project uses Tailwind CSS via the new Tailwind v4 setup.

That means the page is mostly styled by utility classes such as:

- `bg-zinc-50`
- `text-3xl`
- `max-w-6xl`
- `flex`
- `gap-8`
- `rounded-full`

The app/globals.css file is mainly for global resets, theme variables, and shared base styling. Most page design work is done with utility classes directly in the JSX.

## 5. What the homepage file is doing

The current root page is the default starter page generated by Next.js. It is not yet the Clear Choice Media homepage.

The target behavior is:

- render the hero section
- show the service offerings
- display event types and portfolio highlights
- add trust-building content such as reviews and service area copy
- include CTA buttons and a strong booking flow

If you are used to React, this is basically a component tree in one file at first, before we break it into smaller components.

## 6. How to think about building this feature

The recommended approach is:

1. Keep the homepage content in app/page.tsx for the first pass
2. Build the page with sections matching the brief in @project-overview.md
3. Add reusable UI blocks later if the page grows too large
4. Use stock images for now, then swap in real event work later

A simple React-style mental model is:

- Section = a component
- Hero, Services, Portfolio, Reviews = separate JSX blocks
- Data = arrays of objects for services, event types, reviews, and portfolio items
- Map over arrays to render cards and lists

## 7. Next-specific pieces to know

A few things may be new if you mainly work in React:

- Image optimization uses the Next Image component instead of plain img in many cases
- Metadata is defined in app/layout.tsx via the Metadata type
- Routing is file-based, not manually configured
- The app uses the App Router pattern rather than an older Pages Router pattern

## 8. Practical rule of thumb

If you are coming from React, treat this as:

- React for component logic
- JSX for the UI
- Next.js for routing, metadata, and app structure
- Tailwind for styling

That is the main difference between building a normal React app and a Next.js marketing site.
