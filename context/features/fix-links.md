# Button Functionalities
## Goals
Buttons and links should all lead somewhere or do something.  For example, in the More Than Photos section, the links on each card needs a working link. Each link or button should scroll to the appropriate section of the website. If there is no appropriate section, a modal saying coming soon. 

## Implementation

- **Full site audit** covered every interactive element on the homepage: hero CTAs, the 3 "More Than Photos" service cards, section-bottom CTAs (booths, portfolio, video, corporate, wedding), and all three footer link lists (Navigation, Company, Contact).
- **Confirmed policy with user:** action/conversion CTAs with no dedicated matching section (e.g. "Plan Your Corporate Event", "View Wedding Services", "Explore Video", the booths section's bottom CTA) route to `/#contact` rather than showing "Coming Soon" — the contact form is a real, working destination for them. "Coming Soon" is reserved for genuinely unbuilt destinations.
- **Mapping applied:**
	- Hero primary/secondary CTAs → `/#contact`, `/#portfolio` (also fixed a pre-existing bug: these had `#contact`/`#portfolio` hrefs missing the `/` prefix from the earlier navigation fix, so they wouldn't have worked from non-homepage routes — converted to `next/link`'s `Link` for consistency).
	- Service cards: Event Photography → `/#portfolio` (it's the photography showcase), Photo Booth Experiences → `/#booths`, Event Video → `/#video` (via a `SERVICE_LINKS` lookup keyed by title in `app/page.tsx`).
	- Booths/portfolio/video/corporate/wedding section CTAs → `/#contact`.
	- Footer Navigation list (Photography/Photo Booths/Video/Corporate) and Company list (Portfolio/About/Contact) → real `Link`s to their sections; previously these were plain `<li>` text with no interactivity at all.
	- Footer Contact list: email → `mailto:` link, phone ("Call") → `tel:` link (number derived from `content.contact.phone` with non-digit/non-`+` characters stripped).
	- Footer "Reviews" → the one genuine "Coming Soon" case (no reviews section or data exists anywhere in the codebase — it's only ever been a documented future item in `project-overview.md`).
- **New reusable component:** `app/components/ComingSoonButton.tsx` — a self-contained client component (button + its own modal state) taking `label` and `className` props, so any future "not built yet" destination can reuse it without duplicating modal logic.
- **Follow-up fix — repeat-click scroll bug:** Next.js's `Link` skips navigation (and the scroll) when the target URL is identical to the current URL, so clicking a *different* button that happens to point to a hash you're already on (e.g. `/#contact`) silently does nothing. Added `app/components/SectionLink.tsx`, a thin client wrapper around `next/link`'s `Link` that always manually `scrollIntoView`s the target element on click when already on the right page (and updates the URL hash via `history.pushState`), regardless of whether the hash changed — falling back to normal `Link` navigation when the target is a different page (which already scrolls correctly after the route change, per the earlier navigation fix). Replaced every hash-anchor `Link` usage across `app/page.tsx`, `app/components/HeroCarousel.tsx`, and `app/components/NavHeader.tsx` with `SectionLink` (NavHeader's `/admin/login` link is unaffected — it's not a hash link).
- **Follow-up refinement:** "Explore Video →" and "View Wedding Services" changed from directly scrolling to `/#contact` to showing a "Coming Soon" modal (per user follow-up) with an explanatory message and a "Contact Us" button that closes the modal and scrolls to the contact section. `ComingSoonButton` gained optional `message` and `contactCta` props to support this (the plain "Reviews" usage in the footer is unaffected — no `contactCta`, default message). The other `/#contact`-routed action CTAs (booths bottom CTA, "Start Your Project", "Plan Your Corporate Event") were left as direct links since the user only asked for this change on these two.
